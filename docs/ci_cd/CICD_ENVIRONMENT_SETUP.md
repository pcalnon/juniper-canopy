## Overview

Current CI is pip-first. The main test jobs run on Ubuntu and install dependencies via:

1. `pip install torch --index-url https://download.pytorch.org/whl/cpu`
2. `pip install -r conf/requirements_ci.txt`
3. `pip install -e .`

The dependency documentation job also provisions Miniforge to generate conda artifacts, but test execution itself remains pip-driven.

## Python and Tooling Baseline

Recommended local parity:

- Python `3.14` for single-version parity
- Python `3.12`, `3.13`, `3.14` for matrix parity
- `uv` for lockfile maintenance

Install tooling:

```bash
python -m pip install --upgrade pip
pip install uv pre-commit
```

## CI Dependency Files

### `conf/requirements_ci.txt`

Purpose:

- Lightweight CI/test dependency set (includes test + lint + runtime libs)
- Uses CPU-only PyTorch index directive

Notable entries tied to recent CI failures:

- `prometheus-client>=0.20.0`
- `sentry-sdk>=2.0.0`

These are required because observability modules are imported during tests/runtime paths.

### `pyproject.toml`

Defines project extras used by lockfile compilation:

- `juniper-data`
- `juniper-cascor`
- `observability`

## Lockfile Workflow

### Freshness Check Logic (CI)

CI validates `requirements.lock` by recompiling and diffing the content body:

```bash
uv pip compile pyproject.toml \
  --extra juniper-data \
  --extra juniper-cascor \
  --extra observability \
  -o /tmp/requirements.lock.check
tail -n +3 requirements.lock > /tmp/lock_body
tail -n +3 /tmp/requirements.lock.check > /tmp/check_body
diff -u /tmp/lock_body /tmp/check_body
```

The header strip avoids false mismatches from autogenerated `uv` comment lines.

### Regenerating Lockfile

```bash
uv pip compile pyproject.toml \
  --extra juniper-data \
  --extra juniper-cascor \
  --extra observability \
  -o requirements.lock
```

## Optional Testing Extras

Several service-mode tests intentionally skip unless testing extras are installed.

Install when working on adapter/service integration tests:

```bash
pip install "juniper-cascor-client[testing]" "juniper-data-client[testing]"
```

Why:

- Tests call `pytest.importorskip("juniper_cascor_client.testing", ...)`
- Some dataset tests require `juniper_data_client.testing.FakeDataClient`

Without these extras, those tests are skipped (expected behavior).

## Common Setup Validation

Run these checks from repository root:

```bash
# Verify dependency set installs
pip install -r conf/requirements_ci.txt
pip install -e .

# Verify docs link checker script works (CI mode)
python scripts/check_doc_links.py --cross-repo skip

# Verify unit marker subset matches CI selection
python -m pytest \
  -m "not requires_cascor and not requires_server and not slow" \
  src/tests/unit/ src/tests/regression/ -v
```

If these pass, your environment is generally aligned with the active CI jobs.
