# CI/CD Environment Setup Guide

**Last Updated:** 2026-04-04  
**Version:** 0.26.0

Setup guide for the current GitHub Actions CI/CD environment (`.github/workflows/ci.yml`).

## Overview

Current CI is **pip-based** for test/build jobs, with targeted Python matrix coverage and explicit quality gates.

- Runner: `ubuntu-latest`
- Core matrix: Python `3.12`, `3.13`, `3.14`
- Default single-version jobs: Python `3.14`
- Dependency source for tests: `conf/requirements_ci.txt`
- Coverage gate: `80%` (unit/regression job)

## Workflow Triggers

`CI/CD Pipeline` triggers on:

- `push` to `main`, `develop`, `feature/**`, `fix/**`
- `pull_request` targeting `main` or `develop`
- `repository_dispatch` for `data-client-updated`, `cascor-client-updated`
- `workflow_dispatch`

No `paths-ignore` is configured in this workflow, so documentation-only updates still run CI.

## Python Version Strategy

Jobs with matrix:

- `pre-commit`: `3.12`, `3.13`, `3.14`
- `unit-tests`: `3.12`, `3.13`, `3.14`

Jobs with fixed version:

- `integration-tests`: `3.14` (`PYTHON_TEST_VERSION`)
- `build`: `3.14`
- `security`: `3.14`
- `dependency-docs`: `3.14`
- `lockfile-check`: `3.14`
- `docs`: `3.14`

## Dependency Installation Pattern

Unit/integration/dependency-doc jobs use:

```bash
python -m pip install --upgrade pip
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -r conf/requirements_ci.txt
pip install -e .
```

Notes:

- CI installs CPU-only torch explicitly.
- `conf/requirements_ci.txt` now includes `prometheus-client` and `sentry-sdk` used by observability paths.
- Editable install (`-e .`) ensures imports resolve from the source tree.

## Test Selection Environment

Fast CI subsets are controlled via env vars:

```yaml
env:
  CASCOR_BACKEND_AVAILABLE: 0
  RUN_SERVER_TESTS: 0
  ENABLE_SLOW_TESTS: 0
```

Marker filters:

- Unit/regression job: `not requires_cascor and not requires_server and not slow`
- Integration job: `integration and not requires_cascor and not requires_server and not slow`

## Optional Client Packages and Skip Behavior

`src/tests/conftest.py` stubs package roots when client libraries are unavailable, allowing collection to proceed.

Tests that require **real testing helpers** use `pytest.importorskip(...)`, for example:

- `pytest.importorskip("juniper_cascor_client.testing", ...)`
- `pytest.importorskip("juniper_data_client.testing", ...)`

Practical implication:

- CI remains green without `*[testing]` extras.
- These tests are skipped instead of failing collection.

## Docs and Lockfile Guardrails

### Documentation Links Job

CI runs:

```bash
python scripts/check_doc_links.py \
  --exclude templates --exclude history \
  --exclude pull_requests --exclude releases \
  --exclude analysis --exclude fixes --exclude development \
  --exclude CHANGELOG.md \
  --cross-repo skip
```

This validates internal links/anchors while skipping cross-repo link checks in CI.

### Lockfile Freshness Job

CI regenerates a lockfile body and compares it against `requirements.lock` after stripping the autogenerated header lines:

```bash
uv pip compile pyproject.toml \
  --extra juniper-data \
  --extra juniper-cascor \
  --extra observability \
  -o /tmp/requirements.lock.check
```

If stale, CI fails and asks you to recompile `requirements.lock`.

## Artifacts

Common artifacts uploaded:

- `coverage-report-py<version>`
- `unit-test-results-py<version>`
- `integration-test-results`
- `security-reports`
- `dependency-docs`
- `dist-packages`

Default retention is 30 days (90 for dependency docs).

## Troubleshooting

### `exit 134` in Python 3.12 unit tests

CI treats `pytest` SIGABRT during interpreter cleanup as success **only** when JUnit XML reports zero failures/errors.

### Collection errors for optional client test modules

Install optional testing extras locally:

```bash
pip install "juniper-cascor-client[testing]"
pip install "juniper-data-client[testing]"
```

### Lockfile check failure

Regenerate lockfile locally and commit:

```bash
uv pip compile pyproject.toml \
  --extra juniper-data \
  --extra juniper-cascor \
  --extra observability \
  -o requirements.lock
```

### Docs job failures

Run the same command as CI locally (shown above) and fix broken relative links or missing anchors.
