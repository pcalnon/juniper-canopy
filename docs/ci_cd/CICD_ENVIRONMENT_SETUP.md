## Overview

This guide documents the environment assumptions used by current GitHub workflows:

- `.github/workflows/ci.yml`
- `.github/workflows/security-scan.yml`
- `.github/workflows/lockfile-update.yml`
- `.github/workflows/publish.yml`

The project CI is `pip`-based (not conda-based) for test/build jobs.

## Runtime Baseline

Primary runtime values from `ci.yml`:

- `PYTHON_TEST_VERSION=3.14` for most non-matrix jobs
- Matrix testing on Python `3.12`, `3.13`, `3.14`
- Ubuntu GitHub-hosted runners (`ubuntu-latest`)

## Dependency Inputs

CI installs dependencies from:

1. `conf/requirements_ci.txt`
2. Editable install: `pip install -e .`
3. CPU-only PyTorch index: `https://download.pytorch.org/whl/cpu`

Command pattern used in CI:

```bash
python -m pip install --upgrade pip
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -r conf/requirements_ci.txt
pip install -e .
```

This ensures modules needed for test collection (including observability dependencies) are present.

## Required Repository Secrets

### `CROSS_REPO_DISPATCH_TOKEN`

Used by `.github/workflows/lockfile-update.yml` to push lockfile updates from Dependabot branches and re-trigger workflows.

### GitHub default token

`GITHUB_TOKEN` is used by security scanning steps (for example, gitleaks action integration).

## Lockfile and Dependency Sync

`requirements.lock` is verified in CI against `pyproject.toml` extras:

- `juniper-data`
- `juniper-cascor`
- `observability`

Canonical generation command:

```bash
uv pip compile pyproject.toml \
  --extra juniper-data \
  --extra juniper-cascor \
  --extra observability \
  -o requirements.lock
```

Notes:

- `ci.yml` compares lockfile content while ignoring the first two autogenerated header lines to avoid false mismatches from differing `-o` paths.
- `lockfile-update.yml` regenerates lockfiles on Dependabot branches and commits updates automatically.

## Documentation Link Validation Environment

CI validates markdown links with:

```bash
python scripts/check_doc_links.py \
  --exclude templates --exclude history \
  --exclude pull_requests --exclude releases \
  --exclude analysis --exclude fixes --exclude development \
  --exclude CHANGELOG.md \
  --cross-repo skip
```

Behavior:

- Internal repo links are validated.
- Cross-repo links are skipped in CI mode.
- Broken anchors and missing files fail the `docs` job.

## Local Reproduction Checklist

Use this sequence to replicate CI behavior locally:

```bash
python -m pip install --upgrade pip
pip install uv
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -r conf/requirements_ci.txt
pip install -e .
mkdir -p logs src/logs reports/junit reports/coverage reports/htmlcov reports/security
```

Then run:

1. `pre-commit run --all-files`
2. CI-equivalent fast unit/regression pytest invocation
3. `uv pip compile ... -o requirements.lock` lockfile refresh check
4. `python scripts/check_doc_links.py ... --cross-repo skip`

## Troubleshooting

### `ModuleNotFoundError` during test collection

- Reinstall using `conf/requirements_ci.txt` plus `pip install -e .`.
- Avoid relying on local conda-only packages when reproducing CI.

### Lockfile freshness failures

- Regenerate using the exact `uv pip compile` command with all three extras.
- Commit `requirements.lock`.

### Docs job failures

- Run `scripts/check_doc_links.py` locally with CI flags.
- Fix missing file paths or heading anchors.

### Dependabot lockfile job cannot push

- Verify `CROSS_REPO_DISPATCH_TOKEN` exists and has write scope for repository contents.
